Top1Movers Operations Portal: Design System

Version 0.1, September 2026. Phase 1 stakeholder mockup. All names, IDs, and figures in examples are illustrative mock data.

A working screen for dispatchers, warehouse crew, and managers who read tables and clear task lists all day. It should feel like Top1Movers (their navy and red) but behave like a tool: dense, calm, and quick to scan. Everything on this page is built from tokens.css and components.css.

Principles

Navy works, red signs. Navy carries every action, heading, and link. Brand red #E5383B appears only as identity: the logo, a 3px rule, and the current-location marker. It is never a button fill or small text, so red on screen means "brand" or, in its darker danger shade, "trouble".
Scan first, decorate never. 14px body, 40px rows, tabular numbers, sticky headers. Depth comes from borders and tint; shadows exist only on things that float.
Never color alone. Every status pairs a color with an icon and a word, so it reads in glare, on a warehouse tablet, and for color-blind staff.
Built for the touch and the mouse. Same components, two densities: 36px on desktop, 44px on phones and tablets for the field crew.

Color

Neutrals are tinted toward the brand navy so the canvas feels part of the same family as the client's site. Use tokens, never raw hex.

Typography

Inter (variable weight axis, bundled in fonts/; the source is swappable in tokens.css) for everything: headings, nav, buttons, tables, and forms. One family keeps spacing and widths consistent at 12 to 14px, and gives tabular numerals for aligned columns (applied to tables, stats, counts, and inputs only). System mono only for IDs, container and BL numbers. Chrome rests at light-to-regular weights (400 to 500) and grows to 600 for hover, focus, and current states. The client's League Spartan lives in the logo, not in the UI.

Space, shape, elevation

4px base. Tight inside groups (4 to 8), generous between them (24 to 48). More space above a heading than below it.

space-1 4 space-2 8 space-3 12 space-4 16 space-6 24 space-8 32 space-12 48

Radius: sm 8 controls and nav items, md 12 panels, menus and alerts, lg 16 drawers and dialogs. Status pills, count chips, avatars and dots are fully round. Elevation is flat: panels are outlined, not shadowed. --t1m-shadow-float is reserved for menus, drawers, and toasts.

Icons

One family: 24 grid, 1.75 stroke, round joins, currentColor. Rendered at 16px inline, 20px in navigation. Source: icons.svg (this page inlines the same sprite). Add new icons in the same style; never use emoji or text glyphs.

Buttons

One primary per view. Labels name the action ("Create quotation", not "Submit").

Fields

Fields are quiet at rest, darken on hover, and light up with a soft navy halo on focus (a 4px translucent glow plus a navy border), so focus is unmistakable without the hard ring buttons use. Errors swap the halo to red and always carry an icon and a sentence naming the fix.

Dropdown, prefix and suffix, search

The dropdown is a custom listbox: a field-styled trigger, a floating panel with a check on the selected option, a soft highlight for hover and keyboard, optional descriptions and groups, disabled options, and a flip-up placement (data-placement="top") near the bottom of a panel. Arrow keys, Home/End, type-ahead, Enter, and Escape all work. On touch, prefer the native <select>; its picker is better on phones.

Status pills

Always icon + word. Map by meaning: info = in progress, success = done, warning = needs attention soon, danger = overdue or rejected, neutral = not started.

Tables

The core surface. 52px rows at 14px text by default, with a Compact (40) and Comfortable (60) switch. The header is a quiet caps label on a hairline, not a grey band. Hover and selection are inset rounded highlights, and the ID column is emphasized so identity is found first. Row actions appear on hover. Sortable headers (aria-sort), checkboxes with a bulk bar, page size, and / to focus search round out the power tools. Under 640px, ds-table--stack turns rows into labeled cards.

App shell and navigation

White sidebar with a right border (240px, icons-only at 960px and below, bottom bar under 640px), 56px top bar, content capped at 1440px. The sidebar carries the 3px brand-red rule on top; the current item is a navy wash with navy text at weight 600. Hover grows the label heavier instead of changing the background.

Shell preview is hidden on phone-width screens. At this width the sidebar becomes a bottom bar and controls switch to 44px.

Do and don't

Do

  • Use var(--t1m-*) tokens for every color, size, space, and radius.
  • Pair every status color with an icon and a word.
  • Keep one primary button per view, in navy.
  • Use tabular numbers and right-align quantities.
  • Show overdue work and missing documents where people already look (list rows, dashboard, Shipment 360).
  • Give every control hover, focus-visible, disabled, and loading states.
  • Use a drawer for record detail; keep the list visible behind it.

Don't

  • Fill buttons, badges, or banners with brand red. Red is a mark, not a control color.
  • Hardcode hex values, px font sizes, or font names in components. Fonts (bundled, Google Fonts, or any CDN) are declared once in tokens.css.
  • Nest panels inside panels, or wrap every field group in a card.
  • Use emoji or text glyphs as icons.
  • Put a colored side stripe on cards or rows.
  • Use gradient text, glass, or decorative shadows.
  • Open a modal for something a drawer, inline edit, or page can do.

Using it

In the React app: import "@t1m/design-system/components.css" (which pulls in tokens and fonts), then build components that render the ds-* classes documented above. Humans read this page; AI agents read /DESIGN.md and follow /docs/ai/ui-rules.md. If a needed component or value is missing, add it here and to DESIGN.md first, then use it.
